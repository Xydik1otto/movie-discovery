# Telegram-бот «Кіногід» — клієнт до REST API (PLAN.md)

Console-застосунок net8.0 (Telegram.Bot 22.x, long polling). Жодної власної логіки даних —
усе через `API_URL` (дефолт `http://api:5200`).

## Автентифікація (MD-05)

КОЖЕН HTTP-запит до API несе заголовки:

- `X-Bot-Key` — значення env `BOT_API_KEY`; якщо порожнє — заголовок не надсилається
  (авторизація вимкнена), а на старті бот логує попередження.
- `X-Telegram-User-Id` — Telegram user id того, хто натиснув/написав.

Бекенд резолвить профіль користувача з цих заголовків; бот НЕ надсилає `profileId` і
не знає його. Кнопки результатів і пошук «Схожих» працюють з ВНУТРІШНІМИ id тайтлів
(`TitleCard.Id`) — tmdbId у більшості рядків каталогу (IMDb/аніме/манґа) відсутній.

## Конфігурація (env)

| Змінна | Опис |
|---|---|
| `TG_BOT_TOKEN` | токен від BotFather. Порожній → бот логує «TG_BOT_TOKEN порожній — заповніть .env» і чекає (лог раз на 30 с), не падає. |
| `API_URL` | база REST API, дефолт `http://api:5200`. |
| `BOT_API_KEY` | спільний ключ бота і API (обов'язково один і той самий у compose для обох сервісів). Порожній → X-Bot-Key не надсилається, а персональні операції (списки/оцінки) fail-closed: бот показує помилку `bot_key_not_configured` замість мовчазного запису в спільний гостьовий профіль (CR-01). |

## Команди

- `/start` — привітання + інлайн-меню
- `/help` — список команд (укр/англ)
- `/search <назва>` — пошук, 10 результатів на сторінку, кнопки «➕ Хочу подивитись» /
  «✅ Переглянув» (`wl:{id}` / `wd:{id}` з внутрішнім id) і пагінація
- `/find <назва>` — пошук з фільтрами (MD-06, паритет FR-8): інтерактивний конструктор —
  тип (movie/series/anime/manga), жанри (пресети), роки, мінімальний рейтинг; кнопки
  `fi:*` редагують чернетку, «Знайти» виконує `GET /api/search` з
  `type/genres/yearFrom/yearTo/minRating`; пагінація результату зберігає фільтри
- `/similar Назва1; Назва2; ...` — 1–10 еталонів (розділювач `;`); кожну назву бот резолвить
  через `GET /api/search?pageSize=1`, потім `GET /api/similar/by-seeds?ids=<внутрішні id>`
  → топ-10 з причинами
- `/text <опис побажання>` — `POST /api/similar/by-text` (503 → дружнє повідомлення)
- `/watchlist [сторінка]`, `/watched [сторінка]` — `GET /api/lists?kind=…` (профіль
  резолвиться з заголовків) з оцінками
- `/lang uk|en` — мова чата (in-memory; після рестарту скидається на uk — свідоме спрощення Е0/Е1)

Текст без `/` теж трактується як пошуковий запит.

Старі/зламані callback payload'и (не той формат, 0/негативний id, сміття) обробляються
контрольовано: дружня відповідь на callback, жодних дій і виключень. Формати callback
даних короткі (ASCII), ліміт Telegram 64 байти перевіряється тестами.

## Формат

HTML parse mode, усі динамічні рядки екрановані. Постери не надсилаються (Е0/Е1).
Картка: назва + рік + рейтинг + опис (~300 символів) + reasons; посилання TMDB
(`/movie/{tmdbId}` / `/tv/{tmdbId}`) — лише коли tmdbId наявний.
Довгі відповіді автоматично розрізаються на кілька повідомлень (< 4096 символів).

## Структура

```
Program.cs            — конфіг, очікування токена, long polling
Api/                  — HttpClient до API (заголовки X-Bot-Key/X-Telegram-User-Id),
                        моделі (TitleCard, SearchFilters), ApiResult
Bot/CommandParser.cs  — парсери команд/аргументів (юніт-тестуються)
Bot/TextFormatter.cs  — HTML-екранування, обрізання, емодзі, TMDB-посилання
Bot/Renderer.cs       — складання повідомлень + розрізання на чанки
Bot/Keyboards.cs      — інлайн-клавіатури (результати, списки, конструктор фільтрів)
Bot/Strings.cs        — uk/en тексти
Bot/ChatState.cs      — in-memory мова чата + останній пошук + чернетка фільтрів
Bot/TelegramSender.cs — вузька абстракція ITelegramSender + адаптер Telegram.Bot
Bot/BotUpdateHandler.cs — сценарії команд і кнопок
tests/                — xunit (парсери, форматування, API-мапінг, обробник на фейках)
```

## Розробка

```bash
dotnet build   # 0 помилок
dotnet test    # 0 провалених
TG_BOT_TOKEN=123:abc API_URL=http://localhost:5200 BOT_API_KEY=secret dotnet run
```
